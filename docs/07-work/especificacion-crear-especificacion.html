Especificación: skill crear-especificacion

§1 Resumen

Crear una skill de OpenCode que convierta un requisito en una especificación HTML verificable, sin inventar decisiones y sin implementar el resultado.

§2 Objetivos

  • Existe en .opencode/skills/crear-especificacion/SKILL.md.
  • Entrega HTML autocontenido en español con las siete secciones obligatorias.
  • Pregunta y registra toda decisión material antes de entregar.
  • Incluye SVG inline cuando el flujo supera tres pasos.

§3 Fuera de alcance

  • No implementa código ni modifica el producto.
  • No genera planes ni tareas.
  • No rellena políticas, números o roles no definidos.
  • No usa imágenes raster ni recursos remotos.
  • No depende de AgroCortex ni de un caso de clase: el conocimiento del dominio llega por el contexto y las respuestas del usuario.

§4 Diseño

La skill recibe el requisito, consulta contexto, entrevista para cerrar decisiones, redacta las siete secciones y se autoaudita antes de entregar.

§5 Casos borde

  • Si falta una decisión material, pregunta con alternativas claras y no entrega.
  • Si la auditoría revela una suposición, reabre la entrevista.
  • Si el flujo tiene tres pasos o menos, el SVG es opcional.

§6 Criterios de aceptación

CriterioVerificación
La skill tiene nombre, descripción discriminante y reglas duras.Abrir SKILL.md.
La salida contiene §1 a §7 en orden.Generar una spec y revisar títulos.
No inventa una decisión pendiente.Dar un requisito ambiguo y comprobar que pregunta.

§7 Decisiones

Se eligió HTML autocontenido y SVG inline porque así lo exige el encargo del profesor; se descartó Markdown como salida canónica para no contradecir esa convención. Se decidió que la skill sea agnóstica del dominio para que la entrada la determinen el contexto y las respuestas del usuario, no el proyecto.
