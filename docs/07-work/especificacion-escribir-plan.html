Especificación: skill escribir-plan

§1 Resumen

Crear una skill que derive de una especificación cerrada un plan ordenado, asignable y verificable, sin cambiar el alcance acordado.

§2 Objetivos

  • Existe en .opencode/skills/escribir-plan/SKILL.md.
  • Produce tareas con responsable, dependencia, estimación y criterio Sí/No.
  • Señala una primera tarea ejecutable y trabajo diferido.

§3 Fuera de alcance

  • No reescribe ni decide el contenido de la spec.
  • No ejecuta tareas ni edita el producto.
  • No inventa tareas de seguridad, arquitectura o interfaz sin respaldo en la spec.
  • No deja tareas mayores a cuatro horas.

§4 Diseño

Lee la spec, pregunta solamente datos necesarios para planificar, identifica dependencias, deriva las tareas y genera el plan.

§5 Casos borde

  • Si la spec tiene una decisión de producto abierta o un criterio no verificable, devuelve el trabajo a crear-especificacion.
  • Si una tarea supera media jornada, la divide.
  • Si no conoce responsables, los pregunta y no los inventa.
  • Si un riesgo cambia el alcance, registra el bloqueo y devuelve la decisión a la spec en lugar de crear una tarea nueva.

§6 Criterios de aceptación

CriterioVerificación
El plan se activa con una spec y no con un requisito vago.Probar ambos mensajes sin nombrar la skill.
Cada tarea tiene dueño, dependencia y criterio binario.Revisar una tabla de plan generada.
No hay tareas de más de cuatro horas.Revisar estimaciones.

§7 Decisiones

Se eligió docs/PLAN.md como salida por ser revisable en Git; se descartó mezclar el plan con la spec porque cambian a ritmos distintos.
