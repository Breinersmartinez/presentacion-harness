Especificación: skill frontend-design

Estado: descartada y reabierta. La skill canónica de frontend-design es el SKILL.md del profesor (diseño web distintivo); esta especificación de decks de presentación HTML con identidad fija queda archivada hasta nueva decisión.

§1 Resumen

Construir una skill que convierta una petición de exponer un tema en una presentación de slides en un solo HTML: el usuario aporta el contenido y la skill lo organiza en slides y lo maqueta con una identidad visual fija, sin red, sin instalación y navegable con las flechas o el clic. Es la skill que el profesor usa tal cual para sus presentaciones.

§2 Objetivos

  • Genera un único archivo docs/presentacion-<tema>.html que abre con doble clic en un navegador moderno, sin instalar nada y sin internet.
  • Reproduce fielmente el contenido que entregó el usuario: cada punto aportado aparece en el deck y nada inventado se agrega.
  • Aplica la misma identidad visual fija en cada petición: dos presentaciones distintas se ven del mismo sistema visual.
  • Navega adelante y atrás con las flechas del teclado o el clic, sin recargar la página.
  • Si la petición llega sin contenido, pregunta por él y no genera el HTML.

§3 Fuera de alcance

  • Redactar el contenido: el skill no inventa guiones, cifras, nombres, fechas ni citas; solo maqueta y organiza lo que el usuario aporta.
  • Temas personalizables: no se pregunta por paleta, tipografía ni estilo por presentación; la identidad visual es fija y propia de la skill.
  • Recursos remotos: no se usan imágenes, fuentes, iconos ni scripts externos; todo queda embebido en el archivo.
  • Formatos adicionales: no se generan PDF, imágenes, GIF ni videos; la salida es el archivo HTML.
  • Diseño de aplicaciones: no se diseñan pantallas ni prototipos de software; la skill solo produce decks de presentación.
  • Dependencias del proyecto: la skill funciona para cualquier tema y no depende de AgroCortex ni de un caso de clase.

§4 Diseño

La skill recibe una petición (tema) y el contenido a exponer. Si el contenido no está completo, lo pide antes de producir nada. Luego estructura las slides, las maqueta con el sistema visual fijo y entrega un único archivo navegable. Todas las slides viven en el documento: el JavaScript solo conmuta la visibilidad y responde a las flechas y al clic; si el JavaScript está desactivado, el contenido sigue legible por scroll.

Sistema visual fijo de la skill (aplicado igual a toda presentación): paleta verde oscuro #174326, acento #28613b, fondo claro #f6f8f6, texto #1c2820; tipografía system-ui; portada con título y subtítulo, slides con encabezado y pie.

§5 Casos borde

SituaciónComportamiento esperado
La petición llega sin contenido.La skill pregunta por el contenido y no genera el HTML hasta recibirlo.
El usuario pide colores o estilo de su marca.Se responde que la identidad es fija y se aplica el sistema propio de la skill.
El usuario pide incluir una imagen o logo externo.No se carga ningún recurso remoto; se comunica la restricción y se maqueta sin ese recurso.
El contenido es largo para una sola slide.Se parte en varias slides manteniendo el orden y jerarquía del contenido aportado.
El navegador tiene el JavaScript desactivado.Las slides quedan apiladas en el documento y el contenido se lee por scroll.
El usuario pide redactar él mismo las frases de una slide.Se maqueta con las frases entregadas sin reescribirlas.
